# `@cldmv/jsonv` v1.2.2 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/1.2.2`

---

## Overview

v1.2.2 is a development-tooling release. The test config now resolves the package through the `jsonv-dev` export condition the way it was meant to, and the type scripts use the fleet names `types:check` and `types:build`.

No library code changed. The parser and every public specifier are the same as in v1.2.1, and nothing changes for anyone installing the package.

---

## 🔧 CI & tooling

### Tests run against `src/` through `devCondition()` ([#121](https://github.com/CLDMV/jsonv/pull/121))

`.configs/vitest.config.mjs` set `test.nodeOptions` to pass `--conditions=jsonv-dev` to the test workers, but vitest has no such option, so the condition never reached them. The config now builds on `devCondition()` from `@cldmv/configs` (bumped to `^1.4.0`), which sets the resolver conditions and the worker `execArgv`, so Node's own resolver picks `src/` through the `jsonv-dev` export condition too.

### Type scripts renamed to `types:check` and `types:build` ([#123](https://github.com/CLDMV/jsonv/pull/123))

- `test:types` is now `types:check` (`tsc --noEmit` on `.configs/tsconfig.build.json`), and CI's type-check step runs it.
- `build:types` is now `types:build`, which emits the declarations. `npm run build` and the comment in `tsup.config.mjs` use the new name.
