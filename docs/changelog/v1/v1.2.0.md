# `@cldmv/jsonv` v1.2.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/1.2.0`

---

## Overview

jsonv moves to the CLDMV library layout. The build switches from `tsc` plus a separate CommonJS wrapper script to tsup, the CommonJS wrappers now sit beside the ESM files they load instead of in a `dist/cjs/` folder, and the broken `json-dev` export condition is replaced by a working `jsonv-dev` condition. Every public specifier (`@cldmv/jsonv`, `@cldmv/jsonv/parser`, `@cldmv/jsonv/<year>`, `@cldmv/jsonv/loader`, `@cldmv/jsonv/year-resolver`) resolves to the same API as before, through both `import` and `require()`. The parser source did not change.

The package now declares `engines.node` `>=22.22.0`, up from `>=18.0.0`. That is a real requirement change for anyone still on Node.js 18 or 20; see the upgrade notes.

---

## ✨ Features

### CLDMV library layout ([#112](https://github.com/CLDMV/jsonv/pull/112), closes [#110](https://github.com/CLDMV/jsonv/issues/110))

- **tsup build.** tsup compiles `src/**/*.mts` file by file into `dist/` with no bundling, so every year module stays its own file and all entries share one copy of the parser and the error classes. Output keeps the `es2022` target the `tsc` build used (jsonv also runs in browsers) and is now minified with function and class names kept. `generate:years` reads `PUBLISHED_YEARS` from the source now that the built resolver is minified.
- **CommonJS wrappers beside their ESM files.** The root CommonJS entry is a hand-written `src/index.cjs`, copied verbatim to `dist/index.cjs` next to `dist/index.mjs`. The generated per-module wrappers are `dist/years/<name>.cjs` beside each `dist/years/<name>.mjs`. `dist/cjs/` and `dist/types/cjs/` are gone; `main` and every `require` export point at the new files, and `require` type resolution for the year subpaths now uses the same `dist/types/years/*.d.mts` declarations as `import`.
- **`jsonv-dev` export condition.** The old `json-dev` condition pointed `import` at a `src/index.mjs` and `require` at `src/cjs/*.cjs` files that don't exist, so it could not load. It is renamed `jsonv-dev` and maps only `import` to the TypeScript source in `src/`; the test suite runs with it, so tests exercise `src/` without a build. `require()` always resolves to `dist/`, with or without the condition, because there is no `src/index.mjs` for a CommonJS wrapper to load.
- `prepack` now builds the package, and sourcemaps are generated for local debugging but left out of the published tarball.

## 🐛 Bug Fixes

### Broken `./test/*` export and `dev` script removed ([#112](https://github.com/CLDMV/jsonv/pull/112), fixes [#113](https://github.com/CLDMV/jsonv/issues/113))

The `./test/*` export pointed at `./test-dynamic.mjs`, a file that is neither in the repository nor in the package, so any import through it failed. The `dev` script ran plain `node` with the dev condition, which loads `src/*.mts` and fails on its sibling imports outside a TypeScript-aware tool. Both are removed.

## 🔧 CI & tooling

- **Node.js floor raised to 22.22.0** ([#112](https://github.com/CLDMV/jsonv/pull/112)). The dev toolchain (`tsup` 9 and its `chokidar` 6 dependency) needs Node.js 22.22, so nothing older can be built or tested. `engines.node`, the CommonJS guard message and the CI and publish matrix floors (previously 22.12.0) move together. The layout work first set `^20.19.0 || >=22.13.0`; that never shipped.
- CI's coverage legs run `build:ci`, and the bundle-size check measures the `.mjs` and `.cjs` files in `dist/`.
- `tests/cjs/entry.test.cjs` runs with `--conditions=jsonv-dev` and covers `dist/index.cjs`, a year wrapper, the verbatim copy of `src/index.cjs`, where the wrappers sit, and `require()` by package name with and without the condition.
- TypeScript stays on 6.x, because `typescript-eslint`'s peer range stops below 6.1 ([#114](https://github.com/CLDMV/jsonv/pull/114)).

## Upgrade notes

- **Node.js 22.22.0 or later is now required.** v1.1.5 declared `>=18.0.0` for `import` and needed ^20.19.0 or >=22.12.0 for `require()`. On an older Node.js, npm warns with `EBADENGINE` on install (or refuses, with `engine-strict`), those versions are no longer built or tested, and the CommonJS entry's guard message now names `>=22.22.0`. Browser use is unaffected.
- All public specifiers keep their names and exports, through `import` and `require()`. Code that reached into `dist/cjs/` by file path, bypassing `exports`, needs to use the package specifiers instead.
- The `json-dev` condition is gone. It never resolved to existing files; use `jsonv-dev` (ESM only) in a checkout.
